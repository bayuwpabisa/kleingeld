# Plan 18 Nov 2026: Budget per kategori (batas bulanan, progress bar, peringatan ≥80%)

Dikerjakan mulai 26 Nov (jadwal bergeser; task dikerjakan berurutan).

## Context
Task jadwal 18 Nov: **Budget per kategori: batas bulanan, progress bar, peringatan >80% → "budget jalan dan muncul di dashboard"**. Scope (`docs/mvp-scope.md`): atur batas budget per kategori, lihat terpakai vs batas dengan peringatan saat mendekati (≥80%) atau melewati batas; dashboard menampilkan status budget. User story 6 (atur budget bulanan per kategori) dan 7 (peringatan saat hampir/lewat batas).

Sebelum task ini: PR #24 (grafik dashboard) di-squash ke `develop` pada 26 Nov (`f273356`, `ci` + Vercel hijau). Belum ada tabel budget, belum ada `features/budgets/`, dan `/budgets` masih placeholder. DESIGN.md › Komponen sudah menetapkan **Meter budget**: track 8px `bg-surface-muted` `rounded-full`; <80% isi `primary`, label "45% terpakai" `fg-muted`, border biasa; ≥80% isi `warning-fill`, ikon segitiga + "85% · hampir habis" `warning`, border `warning-fill`; >100% isi `danger` penuh, ikon lingkaran-seru + "112% · lewat batas" `danger`, border `danger`; `role="meter"` dengan `aria-valuenow`, `aria-valuemax`, `aria-valuetext`. Token `warning*`/`danger*` sudah ada di `app/globals.css`. Wireframe 05 (Budget) dan 10 (Form Budget), desktop dan HP; kartu Budget di wireframe 03 (Dashboard).

Keputusan user (26 Nov):
- **Batas tetap per kategori**: satu batas per kategori pengeluaran, berlaku setiap bulan sampai diubah atau dihapus; pemakaian = pengeluaran kategori itu di bulan berjalan. Form tanpa field "Bulan" (menyimpang dari wireframe 10; riwayat per bulan bisa ditambah nanti).
- **Bulan ini saja**: halaman Budget dan kartu dashboard memakai bulan berjalan, tanpa navigasi bulan (menyimpang dari wireframe 05).
- **Dialog di semua lebar**: form "Buat budget" / "Atur budget" memakai `Dialog` yang ada (bottom sheet di HP); tanpa route baru dan tanpa slice Redux (menyimpang dari wireframe HP 10 yang memakai halaman sendiri).
- **Seed demo disetel agar 3 state terlihat**: batas dihitung dari pengeluaran bulan ini saat seed (satu ±85% "hampir habis", satu ±112% "lewat batas", sisanya di bawah 80%); batas tetap bila pengeluaran bulan ini masih kecil (awal bulan).

Keputusan saya (bisa dikoreksi user):
- Hanya kategori **pengeluaran** yang bisa diberi budget: kategori pemasukan atau milik user lain ditolak (400 di field `categoryId`). Satu kategori = satu budget (unique; dobel → 409 "Kategori ini sudah punya budget").
- Saat **ubah**, kategori ditampilkan tetap (bukan select); yang diubah hanya batas. Ganti kategori = hapus lalu buat baru.
- Mutation budget **tidak optimistic**: tombol busy sampai server menjawab, lalu invalidasi + toast "Budget disimpan". Hapus = dialog konfirmasi + toast "Budget dihapus" + **Urungkan** yang membuat ulang lewat POST (DESIGN.md › States). Form pendek dan jarang dipakai, jadi kerumitan optimistic tidak sepadan.
- Satu aksi tambah (review wireframe: pilih satu): tombol header **"Buat budget"** di semua lebar; tidak ada tile "+ Tambah kategori budget" / "+ Buat budget baru".
- Grafik "Budget vs realisasi" tidak dibuat (dicoret di `docs/wireframe/mvp-v1/review.md`).
- Level dihitung dengan bilangan bulat (`spent * 100 >= amount * 80` → hampir habis, `spent > amount` → lewat batas). Persen di label dibulatkan **ke bawah**, kecuali saat lewat batas dibulatkan **ke atas**, supaya label tidak pernah bertentangan dengan warnanya: 79,6% → "79% terpakai", tepat 80% → "80% · hampir habis", tepat 100% → "100% · hampir habis", 100,2% → "101% · lewat batas".
- Dashboard: kartu **Budget** di grid bawah setelah Transaksi terbaru (wireframe 03), berisi 3 budget paling mendesak (lewat batas, lalu hampir habis, lalu persen tertinggi) dan "Lihat semua" → `/budgets`.
- Tidak sekarang: navigasi bulan, riwayat batas per bulan, budget untuk pemasukan, salin budget, notifikasi di luar aplikasi.

## Rancangan

### Data
- **Schema** `db/schema.ts` + tabel `budgets`: `id` uuid, `userId` → users (cascade), `categoryId` → categories (**cascade**: kategori terhapus → budget-nya ikut; seed demo menghapus kategori), `amount` bigint > 0 (check), timestamps; `unique(userId, categoryId)`. Migrasi lewat `npm run db:generate` → `db/migrations/0002_*.sql`; diterapkan ke Neon **dev** (`npm run db:migrate`). **Produksi**: user menjalankan migrasi di branch Neon `production` sebelum rilis v0.3.
- **Zod** `schemas/budget.ts`: `budgetInputSchema` (`categoryId` uuid; `amount` memakai field nominal yang sama dengan transaksi: bilangan bulat > 0, maks. `MAX_AMOUNT`, pesan sama; field diekspor dari `schemas/transaction.ts`, tidak diduplikasi), `budgetUpdateSchema` (`amount` saja), query `month` "YYYY-MM", DTO `BudgetStatus` = `{ id, category: { id, name, icon }, amount, spent, count }`. Tanpa impor database, jadi browser bisa memakainya.
- **Repo** `features/budgets/server/budgets-repo.ts` (pola `features/transactions/server/transactions-repo.ts`: ambil `db` + userId, semua query di-scope ke user): `listBudgetStatus(db, userId, month)` (budgets ⋈ categories, ditambah jumlah pengeluaran kategori itu di `monthRange(month)` dari `features/transactions/periods.ts`; urut nama), `createBudget` (kategori harus milik user dan bertipe `expense`; konflik unique → error khusus), `updateBudget`, `deleteBudget`, `getBudget`. Baris user lain terlihat sama dengan baris yang tidak ada (404).
- **Route** `app/api/budgets/route.ts` (GET `?month=YYYY-MM` → `BudgetStatus[]`; POST → 201) dan `app/api/budgets/[id]/route.ts` (PATCH → 200, DELETE → 204). Pola `app/api/transactions/route.ts` dan `[id]/route.ts`: `getCurrentUser` → 401, `readJson` + Zod → 400 dengan bentuk error `lib/api/http.ts`, 404, 409 untuk dobel.
- **Seed demo**: `db/demo/build-demo-budgets.ts` (murni: pengeluaran bulan ini per kategori → baris budget untuk Makan, Transport, Hiburan, Belanja, Tagihan; target ±85% dan ±112% untuk dua kategori, sisanya 40–65%; dibulatkan ke Rp10.000 tanpa mengubah level; batas tetap bila pengeluaran kategori di bawah ambang). Dipanggil `seedDemoUser` setelah transaksi; budget lama ikut terhapus lewat cascade kategori. Ukur waktu seed sebelum/sesudah (login demo produksi ±7,5 dtk).

### Client
- `features/budgets/api/keys.ts`: `budgetKeys.all = ["budgets"]`, `budgetKeys.month(month)`. `fetch-budgets.ts`, `use-budgets.ts`, `use-create-budget.ts`, `use-update-budget.ts`, `use-delete-budget.ts` (`apiFetch`, callback di `useMutation` bukan di `mutate()`, invalidasi `budgetKeys.all`).
- **Mutation transaksi** (`features/transactions/api/use-create/update/delete-transaction.ts`) juga meng-invalidasi `budgetKeys.all`, karena pemakaian budget berasal dari transaksi. Dijaga test di file test masing-masing.
- Murni `features/budgets/budget-status.ts`: `budgetLevel` (ok / warning / over), `budgetLabel` ("45% terpakai" / "85% · hampir habis" / "112% · lewat batas"), `budgetTotals` (total, terpakai, sisa, persen), `byUrgency`, `attentionMessage` ("2 kategori perlu perhatian: Makan hampir habis (85%) dan Hiburan lewat batas (112%)."), `daysLeft(today)` ("untuk 5 hari lagi").
- Bulan berjalan dari `todayInJakarta` di Server Component, diteruskan sebagai prop `today` (pola dashboard).

## Catatan perbaikan
- **B1-1, script bantu (bukan kode repo).** (a) `time-seed.ts` dan `check-demo-budgets.ts` di scratchpad memakai impor absolut `C:/...`; Node ESM di Windows menolaknya (`ERR_UNSUPPORTED_ESM_URL_SCHEME`), lalu bare import `drizzle-orm` dicari dari folder scratchpad (`ERR_MODULE_NOT_FOUND`). Diganti dengan URL `file:///C:/...` dan path paket di `node_modules` proyek. (b) `check.sh` memakai `mkdir -p` untuk folder output; sandbox menolaknya, sehingga dua run pertama mencetak "exit 1" untuk semua langkah tanpa menjalankan satu tool pun. Itu kegagalan script, bukan hasil tsc/eslint/jest; output sekarang ditulis langsung ke folder scratchpad dan run berikutnya exit 0. Pelajaran: script bantu dicoba sekali sebelum dipakai untuk bukti.
- **B2-1, mutation check yang tidak memutasi.** Percobaan pertama mutation (e) menulis `eq(budgets.userId, userId || budgets.userId.name)`, yang tetap sama dengan aslinya karena `userId` selalu terisi; test pasti hijau dan tidak membuktikan apa pun. Terlihat sebelum dijalankan, diganti dengan `ownedBy` tanpa syarat user (update dan delete merah). Catatan ini tertinggal dari commit B2 (`1455073`) dan masuk bersama B3. Pelajaran: baca ulang mutasi dan pastikan perilakunya benar-benar berubah sebelum menjalankan test.
- **B3-1, cast di test.** Draft test invalidasi budget di `mutations.test.tsx` memakai `it.each` dengan `(r as ReturnType<…>)` untuk tiga hook; aturan kerja melarang cast. Ditulis ulang sebelum dijalankan menjadi tiga test terpisah dengan helper `setupWithBudgets`, tanpa cast.
- **B1-2, test yang bergantung data acak.** Draft test "batas tetap di awal bulan" mengharuskan Hiburan < Rp100.000 pada 1 Des 2026, padahal Hiburan muncul acak (7% per hari). Diganti sebelum dijalankan: minimal 3 kategori memakai batas tetap, dan tiap kategori di bawah ambang harus tepat batas tetapnya.
