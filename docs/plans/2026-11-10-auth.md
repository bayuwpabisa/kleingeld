# Plan 10 Nov 2026: Better Auth (Google/GitHub + Coba Demo) dan proteksi route (±2 jam)

## Context
Tugas jadwal 10 Nov: **"Better Auth: Google (OIDC)/GitHub + tombol Coba Demo; proteksi route lewat middleware"**. Output: *login + akun demo jalan, halaman privat terlindungi*.

Kondisi sekarang: `develop` = `56fd7b6` (PR #9, database). `db/schema.ts` sudah punya `users` dengan field inti Better Auth. `seedDemoUser(db)` di `db/demo/seed-demo-user.ts` siap dipanggil login demo. `DEFAULT_CATEGORIES` ada di `db/default-categories.ts`. Semua CTA landing (`app/page.tsx`, `START_HREF`/`DEMO_HREF`) masih ke `/dashboard`. Sidebar punya komentar "Profile and Keluar akun come with sign-in (10 Nov)". Box 6 plan 9 Nov belum dicentang.

Hal yang perlu diingat dari Next 16 di repo ini: middleware bernama **`proxy.ts`**, `cacheComponents: true` (membaca `cookies()`/`headers()` di luar `<Suspense>` = build error; pembacaan sesi dimasukkan ke komponen di dalam Suspense, bukan di top-level layout). Proxy hanya untuk cek optimis. Cek sesi yang sebenarnya dilakukan di server, dekat dengan data (`node_modules/next/dist/docs/01-app/02-guides/authentication-with-cache-components.md`).

## Keputusan
- **better-auth 1.7.x** (`latest` 1.7.19; peer deps cocok dengan Next 16, drizzle-orm 0.45, pg 8). Tanpa dependency lain. CLI `@better-auth/cli` hanya lewat `npx` untuk membandingkan skema, tidak diinstal.
- Adapter: `drizzleAdapter(db, { provider: "pg", usePlural: true, schema })`. Tabel `sessions`, `accounts`, `verifications` ditulis tangan di `db/schema.ts` (gaya yang sama, snake_case), lalu dicocokkan dengan output `npx @better-auth/cli generate` ke scratchpad. Migrasi kedua `0001_*`.
- **Login demo = plugin kecil** (pilihan kamu): endpoint `POST /api/auth/sign-in/demo` → `seedDemoUser(db)` → `internalAdapter.createSession("demo")` → `setSessionCookie`. Tanpa password. Ada rate limit khusus (mis. 5/menit per IP). Client plugin supaya `authClient.signIn.demo()` bertipe.
- **Proxy**: `getSessionCookie(request)` (cek keberadaan cookie saja) untuk `/dashboard`, `/transactions`, `/budgets`, `/bills`, `/settings` (+ subpath). Tanpa cookie → `/login?next=<path>`. `/login` **tidak** di-redirect oleh proxy (supaya cookie kedaluwarsa tidak membuat loop). Halaman login sendiri mengecek sesi asli di dalam Suspense lalu redirect ke dashboard.
- **Cek asli (DAL)** di `lib/session.ts`: `getSession()` (React `cache` + `auth.api.getSession({ headers })`) dan `requireUser()` (redirect `/login` kalau tidak valid, kembalikan `{ id, name, email, isDemo }` saja). Dipanggil oleh kartu profil di app shell, jadi setiap halaman privat memvalidasi sesi. Mulai 11 Nov, API memakai fungsi yang sama.
- `session.cookieCache` 5 menit, supaya validasi tidak selalu query DB.
- **User baru** dapat salinan `DEFAULT_CATEGORIES` lewat `databaseHooks.user.create.after`. Helper `defaultCategoriesFor(userId)` di `db/default-categories.ts` dipakai juga oleh `seedDemoUser` (refactor kecil).
- Provider sosial hanya didaftarkan kalau env-nya ada. Kalau provider gagal atau belum dikonfigurasi, muncul toast error, bukan crash. Ini penting untuk Preview, karena callback OAuth tidak bisa dipakai di URL preview yang berubah-ubah.
- **Env Preview = branch Neon `dev`** (pilihan kamu). Login demo jalan di preview, Google/GitHub hanya di localhost sampai 26 Nov. CI memakai nilai dummy di step Build. `trustedOrigins` diisi dari `VERCEL_URL`/`VERCEL_BRANCH_URL`.
- **Landing "Coba akun demo" langsung masuk demo** (pilihan kamu): komponen `DemoSignInButton` yang sama dipakai di landing dan `/login`. "Mulai gratis" dan "Masuk" → `/login`.
- Avatar memakai inisial nama, belum memakai foto Google/GitHub, supaya tidak perlu `remotePatterns`. Ini juga memudahkan CSP pada 21 Nov.
- Baris "Ketentuan Layanan & Kebijakan Privasi" dari wireframe **tidak** dipasang karena halamannya belum ada.
- `next` di URL divalidasi (`safeNext`: harus diawali `/`, tidak boleh `//` atau `/\`) untuk mencegah open redirect.
