## Context
Tugas jadwal hari ini (Pekan 1): **"Repo GitHub dengan Git Flow (main, develop, feature/*), branch protection, conventional commits, template PR"** → output: *repo dengan aturan branch dan template PR*.

Kondisi repo sekarang:

- Ada pekerjaan 1 Nov yang belum di-commit: `DESIGN.md`, `docs/design-tokens/`, `app/globals.css`, `app/layout.tsx`, `app/page.tsx`, plus revisi wireframe (`docs/wireframe/mvp-v1/updated/`, `review.md`). Ini akan menjadi PR "sungguhan" pertama lewat alur baru.

Batas tugas: Husky/lint-staged/commitlint itu tugas **3 Nov**, dan CI serta required status checks tugas **4 Nov**. Hari ini tidak ada dependency baru, hanya dokumen dan pengaturan repo.

## Keputusan
- **Model branch:** `main` = rilis (Vercel production), `develop` = integrasi, `feature/<nama-kebab>` dari `develop`, `fix/<nama>` untuk bug di develop, `hotfix/<nama>` dari `main` bila produksi rusak. Rilis = PR `develop → main` lalu tag `v0.x` (rilis v0.1 tanggal 8 Nov). `learn/playground` dibiarkan; dia branch belajar, tidak ikut alur, dan dihapus sebelum v1.
- **Strategi merge:** `feature/* → develop` = **squash merge** (judul PR jadi pesan commit, jadi judul PR wajib conventional). `develop → main` = **merge commit** (jangan squash, supaya `main` dan `develop` tidak bercabang). Rebase merge dimatikan.
- **Default branch GitHub = `develop`**, supaya PR baru otomatis menargetkan develop.
- **Proteksi pakai Rulesets** (pengganti branch protection klasik), bypass list kosong, jadi pemilik repo pun wajib lewat PR. Required approvals = 0 karena kamu kerja sendiri (GitHub tidak mengizinkan approve PR sendiri).

## Langkah

### 0. Simpan plan ini ke repo
Salin plan ini ke `docs/plans/2026-11-02-git-flow.md` (folder baru `docs/plans/`, sejajar dengan `docs/learning/` dan `docs/wireframe/`). Isinya tidak memuat data sensitif (tidak ada daftar perusahaan target), jadi aman untuk repo publik. File ini ikut di-commit di langkah 2, dan checklist Progres di atas diperbarui setiap langkah selesai.

### 1. Buat `develop` dan dorong ke remote (lokal, ±5 mnt)
Pekerjaan yang belum di-commit tetap ada di working tree dan ikut pindah branch.
```
git switch -c develop main
git push -u origin develop
```

### 2. Branch `feature/git-flow-setup` → file aturan (±20 mnt)
`git switch -c feature/git-flow-setup develop`, lalu buat:

- **`.github/pull_request_template.md`** — bagian: Ringkasan (apa dan kenapa), Jenis perubahan (feat/fix/docs/refactor/test/chore/ci), Tugas jadwal terkait (tanggal), Cara menguji, Screenshot (untuk UI, mobile + desktop), Checklist: `npm run lint`, `npx tsc --noEmit`, test relevan, a11y (label, keyboard, kontras), tidak ada `.env`/secret, judul PR mengikuti Conventional Commits.
- **`CONTRIBUTING.md`** (di root, karena GitHub otomatis menautkannya di halaman PR) — isi singkat:
  - Diagram alur branch (main / develop / feature / fix / hotfix) dan aturan penamaan kebab-case.
  - Conventional Commits: format `type(scope): deskripsi`, daftar type (`feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert`), scope = nama fitur (`transactions, budgets, bills, dashboard, auth, ui, db`), contoh, dan `!`/`BREAKING CHANGE`.
  - Alur PR: branch dari develop → commit kecil → push → PR ke develop → cek checklist → squash merge → branch terhapus otomatis.
  - Alur rilis: PR develop → main (merge commit) → tag `v0.x` → GitHub Release.
  - Catatan: commitlint + Husky menyusul 3 Nov, status check CI wajib menyusul 4 Nov.

Commit: `docs: add pr template, contributing guide and git flow plan` (termasuk `docs/plans/2026-11-02-git-flow.md`), lalu push.

### 3. Pengaturan repo di GitHub web UI (kamu yang klik, ±20 mnt)
Lakukan **sebelum** merge PR langkah 2, supaya PR itu sudah lewat aturan baru.

1. **Settings → General → Default branch** → ganti ke `develop`.
2. **Settings → General → Pull Requests**: centang *Allow merge commits* dan *Allow squash merging* (default message: *Pull request title and description*), matikan *Allow rebase merging*, centang *Automatically delete head branches*.
3. **Settings → Rules → Rulesets → New branch ruleset**, nama `protect-main-develop`, enforcement **Active**, bypass list kosong, target branch: `main` dan `develop`. Rules:
   - Restrict deletions
   - Block force pushes
   - Require a pull request before merging → required approvals **0**, centang *Require conversation resolution before merging*
   - (Require status checks **belum**, ditambah 4 Nov setelah CI ada)
   - Jangan centang *Require linear history*, karena bertabrakan dengan merge commit develop → main.

### 4. Buka PR pertama dan merge (±5 mnt)
Buka PR `feature/git-flow-setup → develop` di web, pastikan template muncul otomatis, isi, lalu squash merge dengan judul `docs: add pr template, contributing guide and git flow plan`.

### 5. Commit pekerjaan 1 Nov lewat alur baru (±10 mnt, sesuai rencana di memori)
```
git switch develop && git pull
git switch -c feature/design-tokens
```
Dua commit terpisah supaya tetap satu tugas per commit:
- `feat(ui): add design tokens and wcag aa palette` → `DESIGN.md`, `docs/design-tokens/`, `app/globals.css`, `app/layout.tsx`, `app/page.tsx`
- `docs: add revised wireframe and round-2 review` → `docs/wireframe/mvp-v1/updated/`, `docs/wireframe/mvp-v1/review.md`

Sebelum commit: `npm run lint`, `npx tsc --noEmit`, `npm run build` (ingat gotcha: kalau `tsc` error karena `.next/types/validator.ts` basi, hapus `.next`). Push, buka PR ke `develop`, isi template, squash merge.

Catatan: `AGENTS.md` bisa ikut berubah karena `next dev` menulis ulang bloknya. Kalau muncul di diff, commit saja bersama pekerjaan ini.
